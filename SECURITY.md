# Security policy

## Supported version

Security fixes are applied to the latest revision of the default branch.

## Reporting a vulnerability

Do not open a public issue for a suspected vulnerability, exposed credential,
restricted dataset, customer information, precise facility information, or
other sensitive material.

Use GitHub's **Report a vulnerability** feature on the repository Security tab.
Include:

- the affected revision and component;
- reproduction steps that do not contain sensitive production data;
- the likely impact; and
- any suggested mitigation.

Do not upload secrets, operational telemetry, customer content, exploit data,
or private environment details. The maintainers will acknowledge the report,
assess scope, and coordinate remediation and disclosure through the private
advisory.

## Research-data incidents

If restricted data is committed or exposed, stop using or redistributing it and
report it privately through the same channel. Do not copy it into another
branch, fork, issue, log, screenshot, or prompt.
